# @jp/database

- Schema files: `src/schema/{kernel,shared,modules}.schema/*.schema.ts` (buckets = ADR-0016). New table/enum → register in `src/schema/registry.ts`. drizzle-kit globs `*.schema.ts` for migrations; runtime client reads the `registry` aggregator.
- Enums: `*.enums.schema.ts` wraps `@jp/domain-types` VALUES in `pgEnum`. Never fork the list.
- Remove enum VALUE: Postgres no `DROP VALUE`, so `db:generate` emits column->text -> DROP TYPE -> recreate -> USING-cast-back. SAFE only if 0 rows hold removed value (verify first); recreate IS required here (unlike RENAME false-destructive case → hand-write `ALTER TYPE ... RENAME VALUE`).
- IDs/mixins: `uuidv7PK()`, `timestamps`, `immutableTimestamp` in `src/columns/`; `lifecycle()` + `localizedLabel()` in `shared.schema/mixins.ts`. Enum/FK column-sets = functions (fresh builders); plain = objects.
- `timestamps.updatedAt` `$onUpdate` fires on `.update()` ONLY, not `onConflictDoUpdate` — set `updatedAt: new Date()` manually in the upsert `set` clause.
- `db:generate`/`db:migrate` need env (no dotenv wrapper): `export DATABASE_URL="postgresql://postgres:postgres@localhost:5432/petition_management"` (after `docker compose up -d`).
- `db:migrate` = ALL pending in ONE tx + ora spinner EATS pg error under non-TTY (only `exit 1`; failing late migration rolls back earlier DDL → table never lands). Diagnose: run each sql direct — `docker exec <pg> psql -U postgres -d <db> -v ON_ERROR_STOP=1 < drizzle/00XX.sql`.
- drizzle 0.45 = NO `EXCLUDE` builder (hand-write in migration sql). Expression index round-trips clean: `index(...).using("gist", sql\`tstzrange(${a}, ${b})\`)`, confirm re-`db:generate` → "No schema changes". PG18 image has native `uuidv7()` — use in raw backfill sql, not `gen_random_uuid()`.
- `audit_event` = append-only + SURVIVES `TRUNCATE … CASCADE` (kernel table). Backfill/historical scan over `state_after` MUST guard 2 abort cases: orphan `subject_id` (petition wiped) → `AND EXISTS(SELECT 1 FROM petition p WHERE p.id=subject_id)`; enum value the enum dropped (jsonb never migrated) → `AND (state_after->>'status') = ANY(enum_range(NULL::petition_status)::text[])`.
- Invariants → schema (CHECK/unique/FK), not app code.
- `ADD COLUMN … NOT NULL` (no default) FAILS on a non-empty table. Wipe first; FK-pinned tables need the dependents too (e.g. `TRUNCATE medium, petition, submission CASCADE` — medium ← petition/submission). ADR-0051 forward-only-wipe precedent.
- Tests = integration vs real PG. Assert `error.cause.constraint_name` (drizzle wraps PG err; `.message` = "Failed query…"). `vitest.config.ts`: `fileParallelism: false` (shared DB). Composite PK name = `<table>_<cols>_pk`. `user.id` = `text` → FKs use `text`, not `uuid`.
- Integration tests run against a DEDICATED `petition_management_test` DB (same PG container, separate database) — never the dev DB. Both this package's and `apps/api`'s vitest `globalSetup` (`provisionDatabase` from `@jp/database/migrate`) create + migrate it; `testDatabaseUrl()` (canonical: `@jp/database/test/db-url`) is the only URL source: defaults to `*_test`, ignores `DATABASE_URL`, throws unless the name ends `_test`. Point new test files at `testDatabaseUrl()`, never a hardcoded url. No extra docker instance needed. (A dev-DB fallback here once let an unscoped `delete(citizenProfile)` wipe real citizen profiles.)
- Test files share the one `petition_management_test` DB serially (`fileParallelism: false`) and `delete` whole tables in afterEach/afterAll — give each file a unique `TEST_PREFIX` + ward number so a leaked/aborted row can't flake another file's count assertions. Trap: a prefix that is a STRICT prefix of another (`tst-` ⊂ `tst-sib-`) — its broad `like 'tst-%'` cleanup sweeps the other file's rows + FK-aborts on a still-referenced label. Clean by FULL prefix; child tables before parents.
