# @jp/web-public

## React discipline (hook + review enforced — `.claude/hooks/react-discipline.sh`)

- Before writing/refactoring components, consult the `vercel-react-best-practices` + `vercel-composition-patterns` skills. Subagent briefs building UI here MUST embed this block.
- "You Might Not Need an Effect" test on every `useEffect`: runs because the component was *displayed* → effect; runs because the *user did something* → handler; derivable from props/state → compute during render. Effects are ONLY for external systems (mic, map, vibration, timers, DOM listeners).
- External-store subscriptions (`matchMedia`, online, storage, visibility) = `useSyncExternalStore` with module-level subscribe + server snapshot — never useState+useEffect (exemplar: `features/location/location-field.tsx` `useIsDesktop`).
- Heavy client libs (mapbox-gl, three, …) load via `next/dynamic` at the leaf, never a static import — dep-cruiser `mapbox-canvas-dynamic-only` blocks the mapbox case.
- New full-screen field surfaces reuse the shared field grammar: `shared/ui/field-trigger` + `shared/lib/{overlay,haptics}` + voice's clip-path morph recipe (enter 0.5s `[0.19,1,0.22,1]`, exit fade 0.4s) — voice-capture and location-field are the two consumers; don't fork a third grammar. Exit-latch for portal fades = `useOverlayExit` pattern in location-field.
- Component files = declarative skeletons: named module-level parts (never inline components), state in xstate machines, `useState` only for genuine local UI latches.

## Routing & auth law (biome `noRestrictedImports` + `.claude/hooks/routing-auth-law.sh` REJECT violations)

- **NEVER hand-write `/${locale}/…`, and NEVER import `next/link`.** Every internal path resolves from **`ROUTE_REGISTRY`** (`@jp/cms/route-registry`) — the one source shared by the app AND the Payload link picklist. Forgetting the locale prefix is not a typo: `proxy.ts` 307s any locale-less path to its cookie/Accept-Language-negotiated locale twin (`/gallery` → `/en/gallery`) — works, but every such nav eats a redirect. URL locale is the source of truth; the cookie FOLLOWS it (`LocaleSync` persists, never redirects) and only steers locale-LESS entries.
- **Two link buckets, by who chooses the destination.** Editor chooses → Payload `link` field → `actionToCta` → **`<CmsLink cta={cta} />`**. Dev chooses → **`<LocaleLink>`**. `locale-link.tsx` + `cms-link.tsx` are the ONLY files allowed to import `next/link`.
- `<LocaleLink route="gallery">` · `route="home" hash="about-mla"` (home anchor from any page) · `route="petitionDetail" params={{id}}` (**typed — a missing param is a compile error**) · `route="articles" query={{p: 2}}` · `external="https://…"` (auto `target=_blank` + `rel=noopener`). All Next `<Link>` props pass through (`replace`, `scroll`, `prefetch`, `transitionTypes`).
- **Auth-gated CTA → `<EntryLink route="citizenPetitionNew">`** (signed-in → target, else sign-in carrying `?redirect=`). Never re-roll that gate.
- **Imperative nav** (`redirect()`, `router.push`, `replaceState`) → `ROUTE_REGISTRY[key].path(locale)` / `PARAM_ROUTES[key].path(locale, params)` / `signInHref(locale, key)`. Still registry-derived — never a template literal.
- Components take a **route key, not an href string** (`MobileNavItem`, footer/nav link tables). An `href: string` prop reintroduces hand-built paths.
- **Adding a route = one line in `ROUTE_REGISTRY`, no migration.** It only needs `pnpm -F @jp/cms migrate:create` if you ALSO add its key to `EDITOR_ROUTE_KEYS` (each block embedding the link field owns a PG enum of that select; live + `_pages_v_` twin). Dev-only routes stay out of `EDITOR_ROUTE_KEYS` — that's why they're free. Param routes (`PARAM_ROUTES`) can never be editor-pickable.
- **Auth chrome derives from `useCitizenSession()` — the ONE reactive source** (better-auth's nanostore; sign-in/out reflects instantly in every consumer). Direct `.useSession()` outside `shared/auth/use-citizen-session.ts` is rejected.
- **A server session read is a GATE or an SSR SEED — never a frozen `authed`/`isSignedIn` prop drilled into UI.** `resolveCitizenSession()` belongs in route gates (`redirect()`) and in the Suspense-wrapped RSC that seeds `initialAuthed`. Drilling it into a component freezes auth at render time, and Next's Router Cache then serves stale chrome until a hard refresh — that WAS the "profile button doesn't appear until I reload" bug. The seed only covers the pre-hydration tick; the live value always wins.

- Lingui + cacheComponents/PPR: `setI18n` (via `activate(locale)`) MUST run in EVERY route entry (each root layout AND each page) — each renders in its own PPR scope, so missing it makes RSC `<Trans>` throw "i18n instance hasn't been setup".
- Two surfaces = two root layouts (ADR-0040), no `[locale]/layout.tsx`: `(marketing)/layout.tsx` (`<html data-surface="public">`, `globals.css`) + `portal/layout.tsx` (bare `<html>`, `portal.css`). A root layout renders `<html>`; a shared `[locale]` parent would re-merge the documents. `portal` is a real segment (URL prefix) not a `()` group — multi-root forbids it colliding with the `[slug]` catch-all.
- **Locale is NOT request-time data — never `useParams()` for it (biome-banned).** `useLocale()` (`shared/i18n/locale-context`) is the ONE source; both root layouts sit at `[locale]` (which HAS gSP), await it, and hand it down via `<LocaleProvider>`. `useParams()` returns the WHOLE params object, so on a `[id]`/`[slug]` route the unresolvable id poisons the hook and drags `locale` down with it — `LocaleLink` is the leaf of every link on the site, so that made cacheComponents throw blocking-route site-wide. Suspense-wrapping links is the patchwork trap: it streams a value that is neither slow nor varying. Same shape as next-intl (`NextIntlClientProvider` → typed `useLocale()`). Next's own fix menu is cache-or-stream — this is *cache*: make the value stable so it prerenders.
- Any OTHER request-time data read MUST be `<Suspense>`-wrapped or cacheComponents throws blocking-route. That's not just server request-APIs (cookies/`draftMode`) — also: (a) client hooks `usePathname`/`useSearchParams` on routes with a non-gSP dynamic segment (see `desktop-nav.tsx`; `locale-toggle.tsx` has the wrap-with-identical-fallback pattern); (b) `await params` in a page body on such segments — pass the `params` PROMISE into a Suspense-wrapped child and await there (exemplar: `portal/petition/[id]/page.tsx`, nested boundaries keep the id-named VT morph shell). If the value is only used in an event handler, don't subscribe at render at all — read `window.location.*` in the handler (see `report-problem.tsx`). Split into a `<Suspense>` shell + inner async component (see `[slug]`, `portal/me`).
- `@jp/i18n` `createI18nServer(loadMessages)` loader is SYNC → static-import compiled catalogs in `shared/i18n/catalogs.ts` (no async `import()`). Edit translations in `locales/*.po`, then `pnpm lingui:compile`. `prebuild` recompiles so committed `.ts` can't drift from `.po`.
- Compiled `src/shared/i18n/locales/*.ts` = generated + committed (like routeTree.gen.ts), biome-ignored via root `!!**/i18n/locales/*.ts`. Lingui hardcodes `/*eslint-disable*/` in them (not configurable; harmless — biome never reads them). `@lingui/swc-plugin` is knip-ignored (string ref in next.config, not imported).
- `@lingui/swc-plugin` pinned == `@lingui/core` version (catalog), wired in `next.config.ts` `experimental.swcPlugins`. ABI mismatch fails SILENTLY (macros untransformed → raw English renders) — the Tamil e2e assertion is the guard.
- Server-first (ADR-0024/0025, amended by ADR-0055): no oRPC browser client; pages render RSC-first. **Portal client islands MAY use TanStack Query** over a **GET route handler** wrapping `citizenApi` (exemplar: dashboard petition list) — `initialData` from RSC, `placeholderData: keepPreviousData` (never skeleton-swap loaded lists), AbortSignal from TQ into fetch. **Server actions = mutations ONLY, never reads** (POST, serial, non-abortable — the audited stale-append race class). `QueryClientProvider` scoped to portal layout, marketing surface stays query-free. FSD `pages`→`views` (Next reserves src/pages); routing = `app/`. dep-cruiser order shared<entities<features<widgets<views<app + `doNotFollow` node_modules.
- **Lenis scroll ownership (marketing surface):** ONE persistent lenis in `(marketing)/layout.tsx` (`SmoothScroll`), NO `autoToggle` — its overflow-`transitionend` sniff missed restarts on route unmount (site froze until reload; with autoToggle even `lenis.start()` can't force a restart). A view that captures scroll owns it EXPLICITLY: `useLenis()` + effect `held ? lenis.stop() : lenis.start()` with cleanup `lenis.start()` (exemplar: gallery-view). `data-lenis-prevent` means "lenis, hands off — let this element scroll NATIVELY" (nested-scroller semantics), NOT "block scroll" — a non-scrollable overlay must ALSO swallow wheel with a native non-passive listener (React `onWheel` is passive, can't cancel). Stopped lenis `preventDefault`s all wheel site-wide — a stuck-frozen page after navigation = lenis `isStopped` leaked.
- **Icon-beside-text alignment = ADR-0077 tokens, never eyeballed nudges.** Standalone icon next to text: container `items-baseline` + icon `translateY(calc(50% - var(--tbn-icon-anchor)))`, icon's element carries the text's font-size (exemplar: gallery `.inkIcon`). Inside tribune components it's already handled (`--tbn-ink-shift`). Never render icons as font chars (`▾▶✕`). Alignment "still off"? Measure ink (canvas `actualBoundingBox*`) before touching CSS — methodology in the ADR.
- **Scroll-linked motion = transform/opacity ONLY** — never animate `height`/layout from scroll (reflow per frame, jank on the low-end Androids our citizens use). Collapsing headers = iOS large-title pattern: hero in normal flow scrolls away, slim sticky compact bar cross-fades in (ADR-0055 consequences).
- **Never bump user-visible "seen" state during RSC render** — Next `<Link>` prefetch renders pages server-side and would consume it invisibly. Pattern = pure delta query in RSC + explicit client ack mutation after the UI moment plays (ADR-0055 §3, dashboard Visit).
- **Changed-first / per-viewer ordering never touches keyset cursors** — presentation-hoist within page 1 only (ADR-0055 §2).
- **Don't build custom edge-swipe back gestures** — Android predictive-back + iOS back-swipe own that gesture; route transitions = Next `experimental.viewTransition`, back = browser back (ADR-0055 §5).
- **Shared-element morph recipe** (G3 exemplar: `views/dashboard/ui/{stat-tile-grid,active-filter-bar}.tsx`): two live elements sharing a `layoutId` hide the follower — use invisible always-mounted per-target markers; markers must be ~target-shaped (`inset-0` on a big source = bounds-warp dip); AnimatePresence key-switch stacks flow (entering element measures while exiter still occupies flow, even popLayout) — use a constant-height slot + absolute children. Landing springs = `bounce: 0`. Never swap wrapper element types conditionally (`motion.div`↔`div` remounts children — replays odometer rolls).
- **Route view transitions (ADR-0055 §5, exemplar: card→petition detail):** `experimental.viewTransition: true` on. Forward = `<Link transitionTypes={['nav-forward']}>` wrapping `<ViewTransition name={`petition-${id}`}>`; matching `name` on the detail side morphs. **Streaming trap:** the morph target must paint at capture — render a named shell as the Suspense `fallback` (not `null`), never inside it. **Untyped-nav trap:** the layout `<ViewTransition>` maps `default: 'none'` — NEVER a directional type (a `default: 'nav-back'` slide fires on every untyped nav: tabs, logout, locale toggle — users reported it jarring). Untyped back (`router.back()`/OS gesture — popstate can't carry a type) gets no page slide; the named morph alone reverses, per the Next view-transitions guide. Directional slides = explicitly typed `<Link transitionTypes>` only. `router.back()` (not a `<Link>`) preserves the list's filter+scroll. Anchor persistent chrome with `viewTransitionName` + `::view-transition-group(name){animation:none}`. Gate all `::view-transition-*` under `prefers-reduced-motion`.
- **React experimental exports (`ViewTransition`, `unstable_addTransitionType`) live in Next's vendored `next/dist/compiled/react`, NOT workspace `react@x`** — a `node -e require('react')` check resolves the workspace copy and falsely reports them `undefined`. Types come via `react/canary` (add `/// <reference types="react/canary" />` in one project `.d.ts`, not per-file — "use client" ordering hazard). tsc passing ≠ runtime has it; verify experimental React in the browser.
- **FSD slice internals (mirror web-admin, the reference)**: a feature groups into **sub-slices** (`features/<ctx>/<sub-slice>/`, e.g. `citizen-auth/sign-in/`, `citizen-auth/logout/`) — never dump multiple concerns flat in the slice root. Segments = **filename suffix**, not `ui/model/lib` dirs: `*.machine.ts` (pure xstate, stub actors/actions via `setup()`), `use-*.ts` (the machine `.provide()` wiring + actors live HERE, never inline in the component — see `sign-in/use-sign-in.ts`), `*.tsx` render surfaces. No barrels (`noBarrelFile`); consumers import the file path directly. **Large slices may group cohesive segments into directories** (`api/`, `lib/`, `stt/` — e.g. `petition-intake/voice-capture/`) when flat would crowd the root; still filename-suffix within, still no barrels. Small slices (`sign-in/`) stay flat. The form component is a **declarative skeleton** composing surfaces (`<Header/>`/`<FormError/>`/`<PhoneField/>`/`<OtpStep/>`/`<SubmitFooter/>`), no `{cond ? null : …}` — use `{cond && …}`. Derive step/cooldown state from the FSM (`state.context.*`), never sniff transitions with `useEffect`+`useRef`. Localized error→copy lives in a **component surface** with the Lingui `t` macro at call site (NOT a pure string helper like web-admin's `register-error.ts` — Lingui macros must be in a hook/component).
- Both petition-create experiment arms consume `features/petition-create/draft/` (one context/validate/to-fields/providers/register-actor) — never re-duplicate draft-model code per arm; arms keep only FSM topology + surfaces and stay one-commit-deletable (ADR-0048 write paths must be byte-identical).
- Run `pnpm --filter @jp/web-public dev|build` (dotenv loads root `.env`; needs `SITE_URL`, boot-validated). `proxy.ts` = Next16 middleware rename (export `proxy`); matcher must skip `_next`/api/file-extensions or assets get locale-redirected.
- **Portal is cookie-gated in `proxy.ts`** (2026-07-21): signed-out `/{locale}/portal/*` 307s to `citizenSignIn?redirect=<path+query>` on `pm-citizen.session_token` PRESENCE (+ `__Secure-` variant) — kills the PPR skeleton flash before the RSC gate can run. Presence ≠ validity: the Suspense-wrapped server gate stays authoritative, never remove it. Sign-in path exempt; a new portal-public route needs an explicit exemption there; cookiePrefix change must update `CITIZEN_SESSION_COOKIES`.
- MediaRecorder reports parametrized mime (`audio/webm;codecs=opus`); the intake allowlist (`@jp/domain-types/kernel/intake-audio`) matches the **base type only** — strip `;codecs` before signing the upload (fails both the sign 415 AND register-time asset classification otherwise).
- Payload content = LOCAL API (ADR-0026): `getPayload` from `@jp/cms/config` in `'use cache'` + `cacheTag('pages')`; published reads pass `overrideAccess:true` + `draft:false` (no request APIs → caches clean). Draft path uncached behind `draftMode()` in `<Suspense>`. **A `'use cache'` CMS read fills the STATIC SHELL at build (Next docs) — and `draftMode()` has a static default so it does NOT defer; the Docker build's dummy `DATABASE_URL` then `ECONNREFUSED`s the prerender.** Gate every build-reachable CMS read behind `await connection()` in its uncached orchestrator (`shared/cms/get-page.ts` `getPageForRequest` is the marketing chokepoint) → request-time, still caches + revalidates by tag. Build stays DB-free. No `withPayload`/payload routes here; payload core + native deps stay in `serverExternalPackages`. Field-change → regen cms-admin importMap (see its CLAUDE).
- **Cache handler (ADR-0026 amendment)**: `cacheHandlers.default` → `cache-handlers/default.mjs`, dynamic-imported at RUNTIME from disk — it can NEVER import `@jp/*` (raw-TS workspace exports); hash-key constant is duplicated from `@jp/cache/tags`, guarded by a bridge test. The handler NEVER throws: a module-init throw = one 500 then Next silently falls back to its stock uncoordinated handler (`use-cache/handlers.js:44-49`); every Valkey failure degrades to delegate-only with a 5-min-windowed warn. Prod fail-fast on missing `REDIS_URL` = `src/instrumentation.ts` (boot-time; inert during build — `registerInstrumentation` skipped under `NEXT_PHASE=phase-production-build`). CMS tag bumps arrive via the shared Valkey hash `next:tags`, replayed into the delegate on `refreshTags` (lazy, once per render).
- Next16 cacheComponents: NO non-deterministic API (`crypto.randomUUID`/`Date.now`/`Math.random`) during a Client Component render (incl. `useMemo` init) → prerender error `next-prerender-crypto-client`. Defer to event-time / lazy-init.
- **cacheComponents does NOT unmount the previous route on nav — it hides it in React `<Activity>` (`display:none`, keeps ~3 recent, DOM+state preserved).** So unmount is NOT the teardown seam: anything with an external side-effect that must stop when you leave (media playback — `<video>`/`<audio>`/**YouTube iframe** — timers/intervals, subscriptions, rAF loops) needs an explicit `useLayoutEffect` cleanup; `display:none` alone does NOT stop it (a played video kept audio going on the next page — real bug). Effects run cleanup on hide + re-setup on show (Next "Preserving UI state" → media cleanup, ADR-0026). Canonical exemplar = `entities/video/use-video-playback.ts`: one-owner `playingId` (one plays at a time); layout-effect cleanup nulls it so the active iframe unmounts on hide; `play()` = `flushSync(setPlayingId)` so the iframe mounts INSIDE the click gesture (keeps autoplay activation → one click, not two — the lite-youtube technique in React). Both `views/videos` + `widgets/featured-videos/video-deck` consume it.
- `NEXT_PUBLIC_*` client env: `parseEnv(schema, { NEXT_PUBLIC_X: process.env.NEXT_PUBLIC_X })` — literal member access only (Next inlines that); NEVER spread `process.env` (undefined in browser). `dotenv -e ../../.env` loads it server-side; dev restart after adding.
- Map canvas = `react-map-gl/mapbox` (uncontrolled `initialViewState` + imperative `MapRef.easeTo`; default export shadows global `Map` → rename). No mapbox SDK in `@jp/tribune`. Mapbox: Search Box = text search (suggest/retrieve); Geocoding v6 = coordinate reverse (Search Box reverse is POI-sparse in rural IN). Marketing choreographed-camera exemplar = `widgets/office-location/office-map.tsx` (ADR-0068 D16: gate-latched flyTo, `useMarkReady` tile readiness, proximity mount, boundary + auth-fail degrade).
- Feeding a tribune token to a non-CSS renderer (mapbox/WebGL/canvas): `getComputedStyle().color` returns `oklch`/`lab()` (modern browsers), unparseable by GL JS. Convert to sRGB by painting the resolved colour into a 1x1 `<canvas>` and reading `getImageData` bytes.
- Wizard/portal pages scroll inside `PageScroll` (tribune ScrollArea, mask fade) — any fixed full-screen surface or floating chip in a feature MUST `createPortal(document.body)` or its paint is clipped to the scroll band (navbar/footer bleed through). Portal only render-gated on client state (`{open && createPortal(...)}`) so SSR never sees it.
